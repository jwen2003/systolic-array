# Co-design 决策与后续实验路线

[English](18_codesign_roadmap-EN.md) | [简体中文](18_codesign_roadmap-zh_CN.md)


## 1. 当前决策

[已建立事实] Lite→Burst→并行 packing 在约定 N2/K17、连续供数条件下减少调用周期：244→120→62。V1 物理实现仅覆盖 N2/K2 Core，不能把其频率/面积贴到 V2 数据点上。尚无物理 Pareto Frontier。

下一步先复现并消化数据与契约，再测软件准备和 V2 综合/后端反馈。并行 packing 是候选方案，尚不是所有场景的最终赢家。

## 2. 公平比较与 Pareto

固定工作负载、数值语义、平台、I/O 约束与计时边界。第一轮固定最大 Burst 拍数隔离打包机制；后续允许各方案分别调优 L，再比较各自最优候选。始终保留正确性与源/配置/工具版本证据。

先用模型筛掉明显不利点，以 RTL 校准剩余点；选少数候选在共同约束下综合、布局布线。记录有效周期、面积、achievable clock、关键路径、缓冲/拥塞和验证状态。时序不满足的点不作为目标频率下的可行解。

$$T_{device}=C_{invocation}/f_{implemented}$$

真实软件总时间还包含准备/提交/同步等成本；有重叠时不能简单相加。面积和延迟上同时不被其他可行点支配才属于对应目标的 Pareto 集。没有 activity，不用猜测能耗。后端反馈若暴露译码或 mux 路径，可返回 RTL 改动并重新验证；Frontier 可以迭代。

## 3. 条件触发的硬件机制

| 机制 | 启动依据 | 要回答的问题 |
|---|---|---|
| DMA | Host 逐字/逐任务搬运或 CPU 占用确实限制目标 | 自主搬运能否减少 CPU 参与和开销；若外部带宽已满，DMA 不会凭空增加带宽 |
| 双缓冲 | 连续任务中装载与计算可重叠且收益可覆盖代价 | 更复杂 ownership 能换来多少 steady-state 吞吐 |
| Tiling | 选定 workload 超出容量/shape | 部分和存储、跨 tile 调度、边缘补零和复用如何组织 |
| FPGA | 需要验证资源映射或真实 Host 接口 | DSP/BRAM/时序与 ASIC 差异；映射实验与完整上板分阶段 |

## 4. WS/OS 与 2D→1D 的依赖

WS/OS 可在共同数学/精度契约、可复现 OS 基线、明确 workload 和搬运/Buffer 计数口径之后启动；不要求先实现完整 NPU、DMA 或 DDR controller。比较完整 feeder、权重装载、部分和路径与复用，不能只换 PE 名称或只数 MAC。

时间换空间实验需要明确 PE 数量/面积预算、同一任务、正确的时间复用与部分和存储语义。先模型预测再实现少量点，评估延迟、面积、频率及带宽。2D→1D 是映射实验，不等于已经实现三维物理堆叠或 3D 阵列。

当前主线先完成 V2 本轮文档和性能/物理反馈，再开始独立架构对比；避免同时改变接口、数据流和资源预算而无法归因。

## 5. 完整网络与停止条件

网络映射将层的矩阵拆成硬件任务，规定数据位置、复用、部分和、量化与层间依赖。可以先以软件静态调度完成分析；有明确硬件瓶颈时才增加 RTL。INT18 单块溢出后，Host 用 INT32 求和也不能恢复丢失高位。

WS/OS 和时间空间实验可以形成完整的微架构研究成果，不必用完整 NPU 名称作为退出标准。进入新实现前，用户提出假设和控制变量，模型给出预测，RTL 验证与实测检验，软件/后端反馈修正；文档记录事实、解释和待验证假设，不先承诺所有功能。
